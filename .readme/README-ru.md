### Введение

******

Плагин OpenCC (OpenCC Plugin) добавляет в AutoJs6 преобразование китайского текста на основе [OpenCC](https://github.com/BYVoid/OpenCC). После установки плагина глобальный объект `opencc` в скриптах AutoJs6 сразу готов к работе: одна строка кода преобразует текст между упрощенным китайским, традиционным китайским, гонконгским традиционным, тайваньским традиционным и японским синдзитай, без импорта модулей и без доступа к сети.

Плагин построен на разделении обязанностей между хостом и плагином: хост AutoJs6 предоставляет API `opencc`, который напрямую вызывают скрипты, а плагин в виде отдельного приложения содержит движок преобразования OpenCC и словари. Начиная с AutoJs6 6.8.0 хост больше не включает среду выполнения OpenCC и вместо этого полагается на данный плагин; благодаря этому установочный пакет хоста остается компактным, а движок преобразования можно обновлять независимо от хоста.

******

### Основные возможности

******

- Работает сразу после установки: AutoJs6 обнаруживает плагин автоматически; скрипты могут вызывать глобальный объект `opencc` без перезапуска хоста и без какой-либо настройки.
- 14 стандартных преобразований: охватывают преобразование OpenCC между упрощенным и традиционным китайским, гонконгские и тайваньские варианты и японский синдзитай, включая преобразование тайваньской лексики (например, взаимную замену `软件` и `軟體`).
- 33 скриптовых метода: помимо универсального `opencc.convert(text, type)`, у каждого типа преобразования есть одноименный сокращенный метод, а также 18 методов-псевдонимов и составных методов, таких как `s2jp` и `tw2hk`.
- Полностью офлайн: преобразование выполняется локально на встроенных словарях плагина; плагин не запрашивает сетевое разрешение и не собирает никаких данных.
- Пакеты по потребностям: 4 пакета для одной ABI и пакет `universal` со всеми ABI, поэтому каждое устройство устанавливает только необходимое.
- Многоязычность: сведения о плагине, инструкции по использованию, README и журнал изменений охватывают 10 языков.
- Легковесная фоновая служба: у плагина нет собственного интерфейса; хост пробуждает и привязывает его по мере необходимости, а неиспользуемые соединения освобождаются автоматически.

### Использование

******

1. Обновите AutoJs6 до внутренней сборки 3923 (6.7.1 Alpha4) или новее; выпуск 6.8.0 и все более новые версии удовлетворяют этому требованию.
2. Скачайте и установите APK плагина со страницы [Releases](https://github.com/SuperMonster003/AutoJs6-Plugin-OpenCC/releases) или из центра плагинов AutoJs6; если сомневаетесь, выберите пакет `universal` или загляните в раздел `Как выбрать установочный пакет` ниже.
3. Откройте центр плагинов AutoJs6 и убедитесь, что плагин `OpenCC` распознан и включен; официальные пакеты выпусков автоматически проходят проверку подписи, ручная авторизация не требуется.
4. Используйте глобальный объект `opencc` прямо в скриптах, например `opencc.s2t("汉字")`; require и import не нужны, а после установки плагина не требуется перезапускать AutoJs6.

> Плагин поддерживает устройства с Android 7.0 (API 24) и выше. Если скрипт сообщает об отсутствии плагина или устаревшем хосте, см. раздел `Частые вопросы` ниже.

### Быстрый старт

******

После установки следующий скрипт запускается как есть; в комментариях показан ожидаемый вывод:

```javascript
console.log(opencc.s2t("汉字转换"));     // => 漢字轉換
console.log(opencc.t2s("漢字轉換"));     // => 汉字转换
console.log(opencc.s2twp("鼠标和软件")); // => 滑鼠和軟體
console.log(opencc.t2jp("圖書館"));      // => 図書館
```

Сокращенные методы эквивалентны универсальному методу `opencc.convert(text, type)`; сам объект `opencc` также можно вызывать как функцию, а имена типов преобразования не зависят от регистра:

```javascript
console.log(opencc.convert("汉字转换", "S2T")); // => 漢字轉換
console.log(opencc("汉字转换", "s2t"));         // => 漢字轉換
```

Все методы синхронно возвращают преобразованную строку; преобразование выполняется на локальных словарях и никогда не обращается к сети.

### Типы преобразования

******

Метод `convert` и одноименные сокращенные методы поддерживают следующие 14 стандартных типов преобразования OpenCC, где S означает упрощенный китайский, T — традиционный (стандарт OpenCC), HK — гонконгский традиционный, TW — тайваньский традиционный, а JP — японский синдзитай:

| Тип | Направление |
|---|---|
| `S2T` | Из упрощенного в традиционный |
| `T2S` | Из традиционного в упрощенный |
| `S2TW` | Из упрощенного в тайваньский традиционный |
| `TW2S` | Из тайваньского традиционного в упрощенный |
| `S2TWP` | Из упрощенного в тайваньский традиционный с заменой на тайваньскую лексику (например, `内存` становится `記憶體`) |
| `TW2SP` | Из тайваньского традиционного в упрощенный с заменой на лексику материкового Китая (например, `滑鼠` становится `鼠标`) |
| `S2HK` | Из упрощенного в гонконгский традиционный |
| `HK2S` | Из гонконгского традиционного в упрощенный |
| `T2TW` | Из традиционного в тайваньский традиционный |
| `TW2T` | Из тайваньского традиционного в традиционный |
| `T2HK` | Из традиционного в гонконгский традиционный |
| `HK2T` | Из гонконгского традиционного в традиционный |
| `T2JP` | Из традиционного (кюдзитай) в японский синдзитай |
| `JP2T` | Из японского синдзитай в традиционный (кюдзитай) |

Типы с суффиксом `P` помимо познакового преобразования выполняют и замену лексики, поэтому результат звучит естественно для местных читателей; типы без `P` преобразуют только формы иероглифов, не затрагивая лексику.

`T2JP` и `JP2T` преобразуют между традиционными старыми формами иероглифов (кюдзитай) и японским синдзитай, например `圖書館` и `図書館`; они работают с различиями в формах иероглифов и не являются переводом между китайским и японским языками.

### Скриптовые методы

******

Глобальный объект `opencc` на стороне хоста предоставляет в общей сложности 33 метода: универсальный метод `convert`, 14 основных сокращенных методов и 18 методов-псевдонимов и составных методов. Аргумент `type` метода `convert(text, type)` принимает все 32 имени преобразований (как основных, так и составных) без учета регистра; передача неизвестного типа вызывает ошибку `Unknown OpenCC conversion type`.

14 основных сокращенных методов взаимно однозначно соответствуют типам преобразования из таблицы выше; каждый вызов выполняет одно преобразование в плагине:

```text
s2t   t2s   s2tw  tw2s  s2twp  tw2sp  s2hk
hk2s  t2tw  tw2t  t2hk  hk2t   t2jp   jp2t
```

`s2twi` и `twi2s` являются псевдонимами `s2twp` и `tw2sp` соответственно (`twi` означает Taiwan idiom, то есть тайваньскую лексику) и ведут себя идентично.

Остальные 16 составных методов последовательно объединяют несколько основных преобразований и покрывают направления, для которых нет прямого словаря:

```text
s2jp   = s2t  + t2jp          jp2s   = jp2t + t2s
hk2tw  = hk2t + t2tw          tw2hk  = tw2t + t2hk
hk2jp  = hk2t + t2jp          tw2jp  = tw2t + t2jp
t2twi  = t2s  + s2twi         twi2t  = twi2s + s2t
hk2twi = hk2s + s2twi         twi2hk = twi2s + s2hk
tw2twi = tw2s + s2twi         twi2tw = twi2s + s2tw
jp2hk  = jp2t + t2hk          jp2tw  = jp2t + t2tw
twi2jp = twi2s + s2t + t2jp   jp2twi = jp2t + t2s + s2twi
```

Каждый шаг составного метода является отдельным вызовом плагина; например, `twi2jp` последовательно выполняет 3 преобразования. В плотных циклах и для очень длинных текстов отдавайте предпочтение основным типам, чтобы сократить число вызовов.

### Как выбрать установочный пакет

******

Каждый выпуск включает 5 APK, которые различаются только тем, какие архитектуры процессора (ABI) нативной библиотеки OpenCC они содержат:

| Пакет | Кому подходит |
|---|---|
| `arm64-v8a` | Подавляющее большинство современных телефонов и планшетов Android (64-битный ARM); выбирайте в первую очередь |
| `armeabi-v7a` | Более старые 32-битные устройства ARM |
| `x86_64` | 64-битные эмуляторы x86 и немногочисленные устройства x86 |
| `x86` | 32-битные эмуляторы x86 и немногочисленные устройства x86 |
| `universal` | Содержит все 4 архитектуры и имеет наибольший размер; работает на любом устройстве и остается надежным выбором, если вы не уверены |

Если по ошибке установлен пакет для одной ABI, не соответствующей архитектуре устройства, плагин не сможет выполнять преобразование; установка пакета `universal` решает проблему.

### Частые вопросы

******

#### Как убедиться, что плагин работает?

Откройте центр плагинов AutoJs6: если плагин `OpenCC` виден в списке и включен, хост его распознал. Затем запустите скрипт из раздела `Быстрая самопроверка` выше; вывод `漢字轉換` подтверждает работоспособность.

#### Почему в списке приложений нет значка плагина?

Так и задумано. У плагина нет интерфейса, и он не создает значок запуска; после установки AutoJs6 обнаруживает и вызывает его в фоновом режиме, а все взаимодействие происходит внутри AutoJs6.

#### Скрипт сообщает `Отсутствует необходимый плагин для "OpenCC plugin"`. Что делать?

Это означает, что AutoJs6 не нашел плагин на устройстве. Установите плагин и запустите скрипт снова; перезапуск AutoJs6 не нужен. Если после установки сообщение сохраняется, убедитесь, что плагин не был удален системой или защитным приложением, и проверьте его состояние включения и авторизации в центре плагинов.

#### В чем разница между `s2tw` и `s2twp` (`s2twi`)?

`s2tw` преобразует только формы иероглифов (например, `软` становится `軟`) и не меняет лексику; `s2twp` дополнительно заменяет материковую лексику тайваньской (например, `软件` становится `軟體`, а `鼠标` становится `滑鼠`), а `s2twi` является его псевдонимом. Для текстов, адресованных тайваньским читателям, предпочтителен `s2twp`; когда нужно лишь унифицировать формы иероглифов, выбирайте `s2tw`.

#### Почему `opencc` недоступен в скриптах на движке Node.js?

`opencc` пока доступен только в Rhino, JavaScript-движке AutoJs6 по умолчанию; среда выполнения Node.js соответствующей реализации еще не предоставляет. Связанные планы см. в [ROADMAP.md](https://github.com/SuperMonster003/AutoJs6-Plugin-OpenCC/blob/master/ROADMAP.md).

#### Нужна ли для преобразования сеть? Медленно ли преобразуется длинный текст?

Сеть не нужна; все преобразования выполняются локально на словарях OpenCC, встроенных в плагин. Каждый вызов метода соответствует одному межпроцессному обмену, и даже длинные тексты обычно преобразуются за один обмен; в высокочастотных циклах предпочитайте основные типы, чтобы избежать лишних обменов, которые добавляют составные методы.

#### Какие разрешения запрашивает плагин? В безопасности ли мои данные?

Плагин объявляет только разрешение плагина, используемое для связи с AutoJs6, и не запрашивает чувствительных системных разрешений, таких как сеть или хранилище; его служба защищена тем же разрешением, поэтому другие приложения не могут ее вызвать. Преобразуемый текст остается в памяти устройства и никогда не сохраняется и не выгружается.

### Разрешения и безопасность

******

Плагин и AutoJs6 устанавливают доверие через механизмы разрешений и подписей Android:

- Минимальные разрешения: манифест объявляет только разрешение плагина `org.autojs.permission.PLUGIN` и не содержит чувствительных системных разрешений, таких как сеть, хранилище или камера.
- Двусторонняя защита: служба плагина охраняется тем же разрешением, поэтому привязать и вызвать ее могут только хосты с разрешением плагина (например, AutoJs6); у других приложений доступа нет.
- Авторизация по подписи: AutoJs6 проверяет подпись плагина; официальные пакеты выпусков авторизуются автоматически, а сборки с другими подписями загружаются только после ручной авторизации в центре плагинов.
- Локальная обработка: преобразование целиком выполняется на устройстве; плагин не выходит в сеть, ничего не записывает на диск и не собирает пользовательских данных.

Получайте плагин только с официальной страницы [Releases](https://github.com/SuperMonster003/AutoJs6-Plugin-OpenCC/releases) или из центра плагинов AutoJs6. Пакеты из неизвестных источников могут не пройти проверку хоста или скрывать риски, даже если номер версии выглядит одинаково.

### Интерфейс плагина

******

Следующая информация предназначена для разработчиков хоста AutoJs6 и плагинов; по этим идентификаторам хост обнаруживает плагин и согласует совместимость:

```text
application id: io.github.supermonster003.autojs6.plugin.opencc
plugin id: opencc
engine: opencc
variant: default
service action: org.autojs.plugin.OPENCC
service category: opencc
aidl interface: org.autojs.plugin.opencc.api.IOpenccPlugin
aidl methods: getInfo(), convert(text, conversionType)
minimum host build: 3923 (6.7.1 Alpha4)
conversion library: com.github.brooklet:android-opencc:1.2.2
```

`OpenccPluginService` отвечает на действие `org.autojs.plugin.OPENCC` (категория `opencc`); интерфейс Binder представлен `org.autojs.plugin.opencc.api.IOpenccPlugin` из opencc-api и содержит ровно два метода: `getInfo()` и `convert(text, conversionType)`. Также предоставляется `WakeActivity`, чтобы хост мог пробуждать процесс плагина.

`PluginInfo.supportedAbis` сообщает четыре архитектуры `arm64-v8a`, `armeabi-v7a`, `x86_64` и `x86`, чтобы хост и центр плагинов могли определить доступные варианты; преобразование обеспечивают движок OpenCC и словари из `com.github.brooklet:android-opencc:1.2.2`.

### Сборка и проверка

******

Этот раздел предназначен для разработчиков, которые хотят собрать плагин из исходного кода; обычным пользователям достаточно установить готовые APK со страницы Releases.

Сборка debug APK:

```powershell
.\gradlew.bat :app:assembleDebug
```

Запуск модульных тестов JVM и сборка APK для instrumentation-тестов:

```powershell
.\gradlew.bat :app:testDebugUnitTest :app:assembleDebugAndroidTest
```

Сборка release APK; они подписываются автоматически, если идентификатор подписи настроен в неотслеживаемом `sign.properties`, а неподписанные артефакты публиковать нельзя:

```powershell
.\gradlew.bat :app:assembleRelease
```

Сбор артефактов выпуска с добавлением версии, ABI и дайджеста CRC32 к имени каждого файла:

```powershell
.\gradlew.bat :app:appendDigestToReleasedFiles
```

Сборка и проверка 5 подписанных APK одной командой с созданием `SHA256SUMS.txt` и `RELEASE_NOTES.md` на основе английского CHANGELOG:

```powershell
py scripts\release\prepare_release.py
```

Проверка синхронности многоязычных источников документации и сгенерированных файлов (также контролируется CI):

```powershell
py .python\generate_markdown.py --check
```

Для сборки требуются JDK 17 или новее и Android SDK 36; версии Gradle и плагинов централизованно управляются через `version.properties` и `org.autojs.build.platform-versions`.

### Локализация и генерация документов

******

```text
.readme/common.json
.readme/lang_*.json
.readme/template_readme.md
.readme/template_plugin_instruction.md
.changelog/lang_*.json
.changelog/template_changelog.md
.python/generate_markdown.py
docs/images/screenshots/README.md
docs/images/screenshots/plugin-center-enabled.png
app/src/main/assets/doc/CHANGELOG-*.md
app/src/main/res/values-*/strings.xml
app/src/main/res/raw-*/plugin_instruction.md
```

`strings.xml` содержит локализованное описание плагина и сообщения об ошибках, а `plugin_instruction.md` содержит инструкции, отображаемые в центре плагинов хоста. README и changelog всегда правятся через JSON-источники в `.readme/` и `.changelog/` с последующим запуском `py .python/generate_markdown.py`; сгенерированные файлы вручную не редактируются. Команда `py .python/generate_markdown.py --check` проверяет синхронность источников и сгенерированных файлов.
